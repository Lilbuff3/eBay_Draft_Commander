## 2026-05-21 - Added aria-labels to icon-only buttons
**Learning:** Found multiple instances of icon-only `Button` components without `aria-label` attributes across various frontend components. This is a common accessibility issue for screen readers. Using regex replacement on TSX files can be brittle; it's essential to perform safe string replacements to preserve component logic like arrow functions in event handlers. Opposing controls (like Zoom In/Zoom Out) must have distinct, descriptive labels rather than generic ones. Also, when fixing linter errors alongside UX changes, it's critical to ensure modifications don't introduce new, incorrect rules that break CI environments.
**Action:** When adding missing ARIA labels, carefully consider the context and ensure each button has a unique and descriptive label. Avoid using brittle regex for code modifications; favor targeted string replacements or AST-based tools when available. Always run `pnpm lint` and ensure tests pass locally before committing, avoiding the temptation to broadly disable lint rules or introduce non-existent ones.
